# 免会员手游投屏软件开发方案

> 定位：对标 TC Games 的"安卓真机投屏 + 键鼠玩手游"体验，但**全程免费、无会员、无水印、无广告、无账号**。
> 项目代号：**MirrorPlay**（可替换）。文档版本 v1.2，最后更新 2026-09。
> v1.2 变更：**去掉无线投屏，连接方式统一为 USB 数据线 + ADB**，手机端零安装。相应地移除手机端 App 设计、通道抽象层，工期回到 20 周。

---

## 一、项目背景与目标

### 1.1 要解决什么

手游玩家想把手机画面搬到电脑大屏、用键鼠操作，主流方案有三类，各有硬伤：

| 方案 | 问题 |
| --- | --- |
| 安卓模拟器 | 占用高、部分游戏检测模拟器直接封禁或降画质、账号风控 |
| TC Games 类商业投屏 | 免费版被砍：分辨率锁 640P、帧率锁 60FPS、码率 16M、只能连 1 台设备、按键映射仅部分支持；1080P/120FPS/多开/完整映射/去水印全部要 VIP |
| scrcpy 原生 | 完全免费且性能最强，但是命令行工具，没有图形界面、没有键鼠映射，**游戏玩家用不起来** |

空白点很明确：**scrcpy 的性能 + TC Games 的易用性 + 永远不设会员墙**。

### 1.2 产品目标

- **连接目标**：**仅 USB 有线（ADB）**。插数据线即用，手机端**零安装**、拔线无残留。
- **体验目标**：端到端延迟 ≤ 70ms，1080P@60fps 稳定。
- **功能目标**：投屏 + 音频 + 完整键鼠映射（含摇杆走位、虚拟准心视角、宏/连点）+ 多设备多开 + 录屏截图，全部免费。
- **信任目标**：不上传任何数据、无账号体系、无广告 SDK、无行为埋点、无云端中转。
- **平台目标**：一期 Windows 10/11（手游玩家绝对主流），二期 macOS / Linux。

### 1.3 明确不做（Non-Goals）

- **不做无线投屏**：不做 Wi-Fi 通道、不做手机端 App、不做扫码/局域网发现配对。理由见 1.4。
- 不做模拟器、不做云端串流（走本地直连，保证延迟与隐私）。
- 不做 iOS 支持（iOS 无对等的免越狱采集通道，技术不可行且不合规）。
- 不做游戏辅助外挂：不做自动瞄准、透视、脚本打金、协议破解。键鼠映射属于"输入设备转换"，必须与"自动化作弊"划清界限（见第九节合规）。

### 1.4 为什么不做无线

去掉无线不是妥协，而是让产品更锋利：

| 维度 | 无线方案的问题 | 只做 USB 后的收益 |
| --- | --- | --- |
| 延迟 | 网络传输额外增加 15~60ms，且受路由器、隔墙、干扰影响，抖动不可控 | 链路稳定，延迟可控在 40~70ms， gaming 体验可预期 |
| 权限路径 | 想保住键鼠映射完整性，无线就必须让手机 App 托管 shell 权限（需开无线调试、每次重启后要点一次启动、国产 ROM 会杀后台） | 插线即连，无 ROM 保活适配负担 |
| 开发量 | 需额外做一个手机端 App（授权引导、服务托管、保活、局域网发现、ROM 兼容矩阵） | 省掉约 4 周工期与整个移动端维护成本 |
| 稳定性口碑 | 无线断连是所有投屏工具差评的第一来源 | 差评集中在可控范围内 |
| 用户场景 | 手游玩家本来就是坐在电脑前、手机放支架上 | USB 完全够用；线材还能同时充电（长时间玩手游的刚需） |

> 代价要说清楚：用户必须备一根**支持数据传输**的线，且手机要开一次 USB 调试。这两点会在 4.1 用引导与检测兜底。

## 二、竞品与现状调研

### 2.1 TC Games 免费版 vs VIP（我们要把 VIP 列全做成免费）

| 维度 | TC Games 免费版 | TC Games VIP | 本项目 |
| --- | --- | --- | --- |
| 分辨率 | 640P | 1080P | **不受限（设备原生/自定义）** |
| 帧率 | 60FPS | 120FPS | **不受限（跟随设备）** |
| 码率 | 16M | 60M | **不受限** |
| 设备数 | 1 台 | 5 台 | **不限制台数（PC 性能与 USB 口允许即可）** |
| 按键映射 | 部分（行走/射击/开火/点击） | 全部（拖拽滑动、方向滑动、视角控制、虚拟准心、宏、智能施法等） | **全部免费开放** |
| 录屏水印 | 有 | 无 | **无水印** |
| 手机显示鼠标指针 | VIP | VIP | 免费 |
| 息屏控制 / 剪贴板 / 云存储键位 | VIP | VIP | 免费（云存储改为本地文件导出分享） |

### 2.2 免费开源阵营现状

- **scrcpy**（Genymobile，Apache-2.0）：事实标准内核。免 root、手机端零安装、官方口径延迟 35~70ms、30~120fps、1920×1080 及以上。v2.0 起支持音频转发（Android 11+）与 H.265/AV1；v2.2 起支持摄像头镜像；v2.7 起支持游戏手柄；v3.0 起支持虚拟显示；社区已有 v4.x 版本，客户端从 SDL2 迁移到 SDL3，并显式把 MediaCodec 的 `KEY_PRIORITY` / `KEY_LATENCY` 调到最小以降低编码延迟。**性能天花板，但纯命令行**。
- **QtScrcpy**（C++/Qt + FFmpeg + OpenGL）：补上了 GUI、自定义按键映射（JSON 脚本）、多设备群控。缺点是映射能力偏基础、部分高级参数缺失、近年维护节奏放缓。
- **escrcpy**（Electron）：界面最现代、上手最简单，但 Electron 体积大、资源占用高。
- **AnLink**：免登录、中文 GUI、支持音频，但仅 Windows、更新频率低、Android 14+ 适配滞后。

**结论**：不要从零写内核。站在 scrcpy 协议之上做 GUI + 游戏化增强层，是本方案的核心技术决策，可把工期从"以年计"压到"以月计"。

## 三、总体技术方案

### 3.1 技术路线：复用 scrcpy 协议 + 自研 GUI 与映射层

三条路线对比：

| 路线 | 工作量 | 性能 | 风险 |
| --- | --- | --- | --- |
| A. 完全自研采集/编码/传输 | 极大 | 需长期调优 | 高 |
| B. 复用 scrcpy server + 自研 PC 客户端 | 中 | **≈ 原生 scrcpy** | 低 |
| C. 命令行套壳调 scrcpy.exe | 小 | 受限于进程间管道，音频/输入/多窗口难做精细控制 | 中 |

**选 B**：把 scrcpy 的 Android 端 server 作为"设备侧代理"纳入构建（或直接链接 scrcpy 的 C 客户端核心），自研 Windows GUI 外壳 + 键鼠映射引擎 + 多设备管理器。这样既能继承 scrcpy 的低延迟实现，又能自由做游戏化功能。

### 3.2 架构与数据流

```
┌─────────────── PC (Windows 客户端) ────────────────┐
│  UI 层 (WinUI3 / Qt)                               │
│   ├ 设备管理器    ├ 映射编辑器   ├ 设置/多窗口      │
│   └ OSD 准心层    └ 宏脚本引擎                      │
│  核心层                                             │
│   ├ ADB 通道管理（内置 adb，独占端口）              │
│   ├ 视频：FFmpeg 解码 → D3D11/OpenGL 渲染（零缓冲）│
│   ├ 音频：Opus/AAC 解码 → WASAPI 低延迟播放        │
│   ├ 输入：事件采集 → 控制协议序列化 → 回注设备     │
│   └ 录制：MP4/MKV 封装（复用解码前码流，零重编码） │
└───────────────┬────────────────────────────────────┘
                 │ USB 数据线 + ADB 隧道，1~3 条 socket
┌───────────────┴─────── Android 设备 ───────────────┐
│  scrcpy-server（shell/UID 2000，app_process 启动） │
│   ├ ScreenCapture → MediaCodec 硬件编码(H.264/265) │
│   ├ AudioRecord(REMOTE_SUBMIX) → Opus 编码         │
│   └ Controller → InputManager.injectInputEvent     │
└────────────────────────────────────────────────────┘
```

关键点：server 由 PC 端 adb 推入 `/data/local/tmp`、以 **shell** 用户运行、退出即清理，**手机上不留任何安装痕迹、不需要 root、不需要开任何额外开关之外的东西**。整条链路纯本地，不经过任何服务器。

### 3.3 三条 socket 的分工

| Socket | 方向 | 内容 |
| --- | --- | --- |
| video | 设备 → PC | 设备名 + 编码后码流（带 PTS / 包大小头） |
| audio | 设备 → PC | Opus/AAC 码流，PC 侧维护平均缓冲抗抖动 |
| control | 双向 | PC 输入事件上行；设备剪贴板变更下行 |

> 实践提示：默认"网络角色反转"——客户端先监听端口、server 反向连接，可避免竞态导致的连接失败。

## 四、关键模块设计

### 4.1 USB 连接与设备发现

- **内置 adb**：自打包 platform-tools（Apache-2.0，可再分发），客户端独占端口启动 `adb server`，避免与用户已有 adb "版本不匹配"冲突。
- **热插拔监听**：WM_DEVICECHANGE / SetupAPI 监听设备插拔，自动识别序列号与机型，插上即出现在设备列表。
- **首次连接引导**：分步引导开"USB 调试"（设置 → 关于手机连点版本号 → 开发者选项 → USB 调试），弹授权时勾选"一律允许"。
- **注入权限提示**：部分国产机型（小米/红米等）还需额外开启"USB 调试（安全设置）"才能注入点击，按机型给出不同引导页与一键跳转。
- **故障三步排查**：检测不到设备时，按「线材只能充电 / 未授权 / 驱动缺失」分流提示——这是新手最常见的三个坑，必须给出可执行的下一步而不是一句"连接失败"。
- **驱动兜底**：内置常见 Android ADB 驱动（Google / 主流 OEM），提供一键安装入口。
- **多口并发**：支持 USB 集线器多设备同时连接；提示用户优先插 USB 3.0 口（USB 2.0 可用但延迟上升到 80~150ms）。
- **自动重连**：意外断开后 3 秒内重试，恢复时自动还原上次的窗口布局与映射脚本。
- **退出清理**：断开/退出时清理设备上的临时文件与残留进程，拔线后手机不留痕迹。

### 4.2 视频采集与编码

- 采集：`SurfaceControl` / `MediaProjection` 取屏；支持"息屏投屏"（`--turn-screen-off` 等价能力，省电且保护隐私，长时间挂机玩手游很实用）。
- 编码器优先级：**H.265 → H.264 → AV1**（按设备 `--list-encoders` 结果实测挑选）。H.265 同画质省 30~50% 带宽，但部分低端机编码延迟更高，需做实测回退。
- 低延迟配置：显式设置 MediaCodec `KEY_PRIORITY = 0`（realtime）、`KEY_LATENCY` 取最小值；关闭 B 帧；使用 CBR 而非 VBR 以稳定带宽。
- 参考参数（1920×1080@60fps 游戏场景）：码率 6~8Mbps；`--max-fps=60`；帧率上限跟随设备实际渲染帧率动态调整，避免"追帧"造成的编码堆积。
- 动态自适应：PC 侧统计解码抖动与丢帧率，反馈给设备侧动态降分辨率（1080→720）/降码率，保证"流畅优先于清晰"。

### 4.3 音频转发（含降级策略）

| Android 版本 | 方案 | 说明 |
| --- | --- | --- |
| ≥ 13 | `AudioRecord(playback)` + `--audio-dup` | 手机与电脑同时出声；但部分 App 可声明"不可被捕获"，抓不到 |
| ≥ 12 | `AudioRecord(REMOTE_SUBMIX)` | 开箱即用，转发设备输出、静音手机端 |
| = 11 | 同上 | **启动时屏幕必须解锁**，需短暂伪弹窗让系统认为 shell 在前台，否则捕获失败 |
| ≤ 10 | 不支持 | 自动降级为纯视频，UI 明示"系统版本限制"，并提示用音频线/蓝牙等替代方案 |

- 默认 Opus 128Kbps；设备无 Opus 编码器时自动回落 AAC（错误 `Failed to initialize audio/opus` 的直接对策）。
- 缓冲默认 50ms；纯观看场景可放宽到 200ms 换取不卡顿，游戏场景压到 20~40ms。
- 音画同步：视频默认零缓冲，音频需缓冲，二者天然不对齐——PC 侧以音频为主时钟做轻微视频延迟对齐（±1 帧内），避免"声音快画面慢"。

### 4.4 解码与渲染

- 解码：FFmpeg（libavcodec），优先硬解（Windows 走 D3D11VA / DXVA2），失败回软解并提示。
- 渲染：D3D11 + 交换链，YUV→RGB 走 shader，**零缓冲：解码完立即渲染**，帧堆积时主动丢旧帧保最新帧（游戏场景宁可掉帧不要延迟）。
- 窗口：无边框极简模式（对标 TC Games 极简模式）、窗口置顶、全屏、横屏拉伸去黑边（等比/拉伸/裁切三种可选）。

### 4.5 输入回注

- 默认 `InputManager.injectInputEvent()`（SDK 模式）：支持多点触控、指针 ID 管理。
- **HID 模式**：把 PC 键鼠伪装成 USB 物理设备（scrcpy v1.23+ 支持）。对"屏蔽模拟注入"的游戏更有效，是重要的兼容性兜底——且它同样走 USB，与"只做有线"的路线天然契合。
- **OTG 模式**：不需开 USB 调试即可控制（无画面），作为特殊场景补充。
- 指针管理坑点：注入后必须正确释放 pointer/finger id，否则会出现"手指号被长期占用"导致后续触摸失效——这是开源实现里真实踩过的 bug，需在客户端做 id 池与超时回收。
- 文本输入：走剪贴板/文本注入，实现"用 PC 输入法给手机打字"。

### 4.6 键鼠映射引擎（**本产品核心差异化，重点投入**）

这是 TC Games 拿来卖会员的地方，也是唯一需要真正原创设计的模块。

> **详细设计见配套文档《键鼠映射引擎详细设计.md》**，包含：坐标系统四层转换、完整 JSON Schema、13 类映射的状态机与算法（摇杆向量合成、视角准心与 recenter）、多指 PointerPool 管理、注入节奏与延迟预算、编辑器交互、合规红线与测试方案、M2 阶段 12 项任务拆分。

下面只列出概要。

#### 映射数据模型（JSON，可导入导出分享）

```json
{
  "version": 1,
  "game": "com.tencent.tmgp.pubgmhd",
  "resolution": { "w": 2400, "h": 1080 },
  "items": [
    { "type": "click",      "key": "Key_F",  "pos": { "x": 0.82, "y": 0.61 } },
    { "type": "click_twice","key": "Key_G",  "pos": { "x": 0.70, "y": 0.55 } },
    { "type": "drag",       "key": "Key_R",  "start": { "x": 0.5, "y": 0.4 }, "end": { "x": 0.5, "y": 0.7 }, "durationMs": 120 },
    { "type": "steering",   "keys": { "up": "Key_W", "down": "Key_S", "left": "Key_A", "right": "Key_D" },
                            "center": { "x": 0.18, "y": 0.72 }, "radius": 0.12 },
    { "type": "view",       "mode": "crosshair", "center": { "x": 0.5, "y": 0.5 }, "sensitivity": 1.0 },
    { "type": "fire",       "key": "Mouse_Left", "pos": { "x": 0.88, "y": 0.45 }, "repeatMs": 0 },
    { "type": "macro",      "key": "Key_Q", "steps": [
        { "act": "click", "pos": { "x": 0.3, "y": 0.8 } },
        { "act": "wait", "ms": 50 },
        { "act": "swipe", "from": { "x": 0.3, "y": 0.8 }, "to": { "x": 0.6, "y": 0.8 }, "ms": 100 }
    ]}
  ]

```

坐标一律用**相对值 0~1**，天然适配不同分辨率与 DPI，换机型不跑偏。

#### 必须实现的映射类型（对齐并超越 TC Games VIP 列表）

| 类型 | 说明 | 实现要点 |
| --- | --- | --- |
| click / click_twice | 普通点击、双击 | pointer down/up，间隔可配 |
| drag（拖拽滑动） | 固定起止点滑动 | 分段插值注入，控制 duration 与采样间隔 |
| swipe_direction（方向滑动） | 朝某方向滑动一段 | 八方向 + 自定义距离 |
| sliding_attack（滑动攻击） | 滑动同时触发攻击 | 组合 pointer 序列 |
| steering（摇杆/方向键） | 左手走位 | 四键合成向量 → 归一化到半径内 → 持续注入 pointer move；松开回中 |
| view（视角控制） | 右手转视角 | 鼠标相对位移 → 屏幕中心拖拽；注意指针捕获与灵敏度曲线 |
| crosshair（虚拟准心） | FPS 视角模式 | 鼠标锁在窗口内、绘制准心、右键开镜、移动即转视角 |
| fire（射击/连点） | 左键开火 | 支持按下持续 + 可配连点间隔 |
| macro（宏按键） | 多步序列 | 时间轴脚本，含 wait/click/swipe/key；**限速**，禁止高频无人值守 |
| smart_cast / cancel_cast（智能施法/取消施法） | MOBA 向 | 按键按下显示范围、抬起施放 |
| right_click_move（右键行走） | 右键点哪走哪 | 坐标转摇杆方向 |
| view_extend（视野扩展） | 扩视野 | 屏幕比例/渲染裁切配置 |
| observe（观察视角） | 小地图拖拽视角 | 区域限定拖拽 |

#### 编辑器设计

- 在投屏画面上**所见即所得**：按键拖到屏幕位置 → 选类型 → 调参数 → 实时试玩。
- 内置热门游戏预设（首发 10~15 款主流 FPS/MOBA），支持一键下载云端预设库（纯 JSON 静态托管，无需登录）。
- 支持导入/导出/分享（文件、文本片段），社区可自由交换键位——**这是"云存储"的免费替代方案，也是冷启动口碑来源**。
- 一键切换"映射模式 / 普通触控模式"（如 `~` 键），避免映射误触。

### 4.7 多设备与群控

- 每个设备一个独立窗口 + 独立 server 实例，`scid` 随机 ID 区分同一设备上的多个客户端。
- 群控模式：主窗口操作同步到已勾选设备（坐标按比例映射）。
- 批量安装 APK、批量执行脚本；窗口网格自动排布（2×2 / 3×3）。
- 性能红线：N 台 × 1080P@60 解码对 PC 是线性开销，**且多路 USB 共享主机控制器带宽**，需在 UI 明示推荐配置（建议 USB 3.0 独立口或带供电的 3.0 集线器），并支持"副设备降码率"。

### 4.8 录屏与截图

- 录制**直接复用设备侧码流封装**（MP4/MKV），不重编码，画质无损且 CPU 几乎零开销。
- 支持时间戳命名、区域录制、录制同时静音手机端（避免回声）、**永不加水印**。
- 截图：PC 侧抓当前帧 PNG；也支持 `adb exec-out screencap` 拿原生分辨率。

### 4.9 GUI 设计要点

- 主界面三块：设备列表 / 参数面板 / 映射编辑器；首次运行有"五步上手"引导（插线 → 开 USB 调试 → 连上 → 调画质 → 选键位开玩）。
- 画质分档：流畅 / 均衡 / 高清 / 超清 / 自定义，档位直接映射到分辨率+码率+帧率+编码器组合。
- 全中文、无账号、无登录、设置纯本地 JSON。
- 线材提示：检测到连接不稳定时，主动提示"换一根支持数据传输的线 / 换 USB 3.0 口"。

## 五、技术选型

| 层 | 选型 | 理由 / 许可证 |
| --- | --- | --- |
| 设备端内核 | scrcpy-server（Java，编译进 jar/APK） | 免 root、手机端零安装；Apache-2.0 |
| PC 客户端语言 | C++20（推荐）或 Rust | 需要贴近 FFmpeg/SDL，控内存与延迟 |
| GUI | Qt 6（LGPLv3，动态链接合规）或 WinUI 3 | Qt：跨平台、信号槽异步、社区成熟；WinUI 3：Windows 原生观感 |
| 渲染 | SDL3 / D3D11 + 自绘 shader | SDL 已被 scrcpy 主线采用；D3D11 便于 Windows 硬解联动 |
| 解码 | FFmpeg 6.x（LGPL/GPL 二选一，注意许可证，见第九节） | 硬解兼容性最好 |
| 音频输出 | WASAPI（独占/低延迟共享模式）+ SDL Audio | Windows 低延迟 |
| 通道 | 内置 adb（platform-tools），仅 USB | Apache-2.0 |
| 打包 | CMake + vcpkg；Inno Setup / MSIX | — |
| 配置/键位 | JSON（nlohmann/json 或 Qt QJson） | 便于分享 |

## 六、性能目标与延迟预算

端到端延迟分解（USB 3.0 目标值）：

| 环节 | 预算 |
| --- | --- |
| 屏幕采集 + 硬件编码 | 15~25ms |
| 传输（USB 3.0） | 3~8ms（USB 2.0 会升到 80~150ms 总延迟） |
| PC 解码 | 3~8ms |
| 渲染上屏 | 5~10ms |
| 输入事件回注 | 5~15ms |
| **合计** | **40~70ms** |

优化手段清单：

1. 客户端**零视频缓冲**，帧堆积时丢旧保新。
2. 编码端 `KEY_PRIORITY=realtime`、`KEY_LATENCY` 最小、关 B 帧、CBR。
3. 优先硬解；硬解失败明确提示而非静默降质量。
4. 码率自适应：按丢帧率/抖动反馈闭环下调分辨率与码率。
5. 音频缓冲与视频缓冲按场景预设（游戏 20~40ms / 观影 150~200ms）。
6. 渲染线程、解码线程、输入线程分离，互不阻塞。
7. USB 口选择引导：优先 USB 3.0，避免接在机箱前置面板或劣质集线器上。

## 七、"免会员"怎么活下去（可持续模式）

不卖会员、不卖功能解锁，那靠什么维持？可选组合：

1. **开源 + 自愿捐赠**：GitHub Sponsors / 爱发电 / 支付宝-微信捐赠码，主仓库 Apache-2.0 完全开源，本身即最好的分发与信任背书。
2. **一次性买断（可选）**：卖"离线安装包 + 优先技术支持 + 键位定制服务"这类**服务**，而不是卖软件功能；功能永远 100% 免费，避免违背承诺。
3. **周边/硬件**：低延迟 USB 数据线、手机散热背夹、支架——与产品强相关、不侵入体验（只做有线后，"好线材"的推荐反而更自然）。
4. **企业/批量授权**：面向手游工作室、公会、测试团队的**群控企业版**（多设备编排、批量脚本、集中管理）单独收费，个人版永久免费。
5. **成本侧**：无服务器中转（纯本地 USB 直连）→ 带宽与服务器成本为 0；键位预设库用静态托管/CDN 免费额度即可覆盖。

> 原则写进首页承诺：**永不设会员墙、永不加水印、永不加广告、永不上传用户数据**。这条承诺本身就是对标竞品最强的营销点。

## 九、法律与合规（务必在开工前确认）

1. **开源许可证**：scrcpy 为 Apache-2.0，可商用可修改；Qt 用 LGPLv3 时须动态链接并提供替换能力；**FFmpeg 若启用 GPL 组件则整体须 GPL**，商业闭源需选择 LGPL 构建或取得商业授权——这是最容易踩的坑。
2. **广告/SDK**：本方案不含任何第三方统计、广告 SDK，隐私政策可写成"不收集任何数据"，这是硬承诺。
3. **反外挂红线**：键鼠映射是"输入设备转换"，但**不得**提供自动瞄准、自动压枪、透视、自动打怪、协议破解、内存修改等功能。产品需在显著位置声明"本工具不提供任何游戏作弊功能，用户因违规操作导致的封号责任自负"。
4. **FLAG_SECURE**：部分 App（银行、版权内容、即时通讯等）设置了防截屏标志，系统级采集可能仍能抓取——产品应主动提示用户尊重 App 的内容保护与版权，不以此为卖点宣传。
5. **分发**：Windows 需代码签名证书（否则 SmartScreen 拦截严重影响安装率）；官网与下载页需备案/合规（面向中国大陆用户）。
6. **免责**：不得内置任何破解、去广告、修改游戏客户端的功能；不得捆绑安装。

## 十、风险清单与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 游戏屏蔽模拟注入 | 键鼠无效 | 提供 HID 模式兜底（同样走 USB，与本方案契合）；建立"兼容机型/游戏"众包清单 |
| 国产 ROM 权限差异（需额外开"USB 调试（安全设置）"） | 连接失败率高 | 按厂商做引导页；内置常见机型 FAQ；一键跳转设置页 |
| 用户用的是"只能充电"的线 | 检测不到设备，新手直接放弃 | 故障排查三步分流，明确提示换线；官网推荐线材 |
| USB 2.0 口带宽不足 | 延迟升到 80~150ms | 启动时检测口速并提示换 USB 3.0 口 |
| 多设备共享 USB 控制器带宽 | 多开时集体卡顿 | 提示用带供电的 USB 3.0 集线器；副设备自动降码率 |
| 低端机 H.265 编码延迟高 | 卡顿 | 编码器实测打分 + 自动回退 H.264 |
| Android 11 音频需解锁屏幕 | 音频失败 | 启动时弹伪窗 + 明确提示；失败自动降级纯视频 |
| 部分用户就是想要无线 | 流失一部分潜在用户 | 明确产品定位（低延迟优先）；在 FAQ 说明取舍理由，不为无线妥协主体验 |
| Qt/安装包体积大导致分发成本高 | 安装率下降 | 选 Qt 或原生方案；提供 portable 免安装版 |
| 被竞品/平台误判为外挂 | 口碑与分发受阻 | 首页明确红线声明；不做任何自动化 gameplay 功能 |
| 上游 scrcpy 协议变更 | 升级成本 | 锁定 server 版本；客户端/服务端版本强校验（不一致直接报错） |

## 十一、验收测试用例（摘要）

- 连接：USB 热插拔 20 次无泄漏、无残留进程；多设备同时接入识别正确。
- 线材与口速：分别用充电线/数据线、USB 2.0/3.0 口测试，验证提示信息准确。
- 画质：640P→1080P→原生各档，帧率 30/60/90/120 切换不崩溃。
- 延迟：3 款机型 USB 实测，用高速摄像/PTS 打点法量化，出具实测表。
- 音频：Android 10/11/12/13+/14 各一台，验证降级与 `--audio-dup` 行为。
- 映射：每种映射类型至少 1 个真实游戏用例；跨分辨率（1080P ↔ 720P）坐标一致性。
- 稳定性：连续运行 8 小时无内存增长；拔线重插 50 次成功率 ≥95%。
- 卸载：退出后手机上无任何残留文件/进程（`/data/local/tmp` 清理验证）。
